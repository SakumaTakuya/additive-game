## 優先度の意味

- **A** ＝ 顧客デモの最小構成
- **B** ＝ デモ後に順次。仮画像のままでもアプリは正常に動作します

## 発注しなくてよいもの（作画ゼロで成立する要素）

| 要素 | 理由 |
|---|---|
| **主人公の3姿勢（待機/喜び/疲れ）** | v0.3で主人公を廃止。全住人が待機1姿勢のみ。感情表現は開封カードの演出が担う |
| 敵（寝ぼけ個体）の専用絵 | 既存住人を**くすみ系にパレットスワップ**するだけ。系統の色定義は #00 に含む |
| 図鑑の未発見シルエット | 既存スプライトを**実行時に単色で塗り潰し**て自動生成 |
| 隊長トラッカーアイコン | 既存スプライトの**縮小流用**で検証。視認性不足のときのみ追加発注 |
| ★表示・性格ラベル・開封カード枠・ログ枠・魔力ゲージ・ニックネーム欄 | すべて**コードで描画** |
| キャラの向き違い | **正面固定**が設計原則 |
| 曜日祭壇の絵 | PoCでは編成画面ヘッダの文字表示のみ（「木曜・植物の祭壇」） |
| 装備パーツ | 収集単位は「住人1体まるごと」 |

## 全体で貫かれている設計原則（各指示書にも記載）

1. アウトラインなし・ベタ塗り・グラデーションなし
2. 共通パレットから1体あたり3〜5色（精霊質色を含む）
3. **精霊質色の露出と目を全住人必須**。統一はこれと出自の3点のみ、他は自由
4. 影は1段・紫寄り／光源は左上／接地影は楕円1枚
5. 正面固定・レイヤー分割禁止・丸ごと差し替え単位
6. **小サイズでシルエットと感情の方向が読めること**が全アセットの最優先要件
