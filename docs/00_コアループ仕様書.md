## 1. 概要

『遺跡に住みつく精霊』PoCのコアループを確定する。本仕様は以下の4つの柱で構成される。

1. **セッション区切りはランタン方式（決定論的リソース）に一本化**し、発掘袋を終了条件から外す。開始時点で終了時刻が確定し、完全ローカル完結で実装できる
2. **常駐表示は三層構成**（Widget／ステータスバーチップ＝Android 16 Live Updates／通知シェード）とし、いずれもコア体験の一部として組み込む
3. **モンスターバトル要素を導入する**。バトルは探索中にオート解決し、帰還時にログ形式のリザルトとして見せる。ランタン方式は一切変更しない
4. **住人そのものを毎周の基本報酬とする**。回収のたびに1体以上が必ず目を覚ます（重複あり）。住人1体＝個体差3軸（★・性格・色）をロールされた1つの戦利品であり、収集と厳選がゲームのコアとなる

### 設計の基本原則

**「いつ終わるかは確定、誰がどんな個体で起きるかは開けるまで不明」**

ランダム性を終了条件から回収内容へ完全に移す。終わりは読めるが中身は読めない構造により、帰還時刻に合わせて開けに行く楽しみを作る。「中身」の主役は住人ロールであり、コモン重複の周でも「今回のは当たり個体かも」という開封価値が毎回保証される。バトル結果もこの「開けるまで不明」の側に同居する。

### 本作の系譜

装備を持たない本作では、ハクスラにおける「装備ドロップ」の役割を住人が担う。個体差にはポケモンスリープ等の厳選文法を採用する。

### 主役は誰か（v2.1）

固定の主人公は存在しない。**探索の主役は、プレイヤーが編成した3体のうち1枠目の「隊長」**である。厳選して当てた自慢の個体を隊長にして連れ歩く体験が売りであり、固定の主人公はこれと席を奪い合うため廃止した。旧主人公（スライムの精霊）は他の住人と完全に同列のモチーフ#1となる。

## 2. 世界観上の位置づけ

### 住人の中身＝精霊質

遺跡に溜まる魔力は**精霊質**として現れる。全住人の中身はこの共通の精霊質であり、壺・石柱・化石などの**器**に宿って目を覚ます。スライムの精霊としずくは、器を持たないむき出しの精霊質である。

### バトル＝「倒す」ではなく「鎮める・起こす」

- 敵は専用モチーフを作らず、**まだ目を覚ましていない住人が寝ぼけて暴れている姿**（精霊質が濁った状態＝パレットスワップ）とする
- 鎮めると魔力素材を落とし、**鎮めた成果はその周の覚醒ロールに個体値補正として乗る**
- 「精霊質が満ちると壺や石柱までもが目を覚ます」世界観により、毎周誰かが起きることはむしろ自然で、遺跡が賑わっていく画がWidgetに直結する
- 初期住人リスト10体がそのまま敵テーブルを兼ねる。**敵専用アセットは不要**

## 3. コアループ（1周・数時間スケール）

1. **編成して灯す** — 灯す前に「誰を連れて潜るか」を3枠で選び、ランタンに火を入れて探索開始。**1枠目が隊長**となり、通知のトラッカーとして歩いて帰る。前回編成の引き継ぎをデフォルトとし、最短タップ数（＝「始める」だけ）を維持する。時間指定UIは置かない。開始時点で終了時刻が確定する。良個体を厳選して編成に入れる→バトルが有利→鎮め補正で次の厳選が捗る、という循環がここに接続する

2. **見守る（探索＝バトル）** — 三層の常駐表示で「探索が続いている気配」を作る。ランタンが燃えている間に遭遇と戦闘がオートで解決される。リアルタイム描画はしない
   - **Widget**：遺跡の風景＋留守番組（編成外の住人）＋探索中の演出（袋が膨らむ）。編成メンバーは不在
   - **ステータスバーチップ（Live Updates）**：ランタンのシルエット＋`setWhen` に終了時刻を渡したカウントダウン（OS描画委譲）
   - **通知シェード／ロック画面**：`ProgressStyle` のゲージ上を隊長が歩いて帰る（Android 16未満は通常常駐通知にフォールバック）

3. **帰還** — チップとWidgetが「帰ってきた」状態に切替。回収導線の入口はWidgetと通知の2箇所

4. **回収** — タップで持ち帰り品を開ける＝ガチャの瞬間
   - **住人が1体以上必ず目を覚ます（重複あり）**。「今日は誰が、どんな個体で起きたか」を開ける
   - 各個体は**★（1〜5）・性格・色**の3軸をロール済み。当たり軸が独立して二重三重にあるため、コモンモチーフでも開封価値がある
   - **戦果の反映**：鎮め成功数に応じて★分布が上方シフト。PoCでは早期帰還を起こさない。将来導入する場合も全損なし（表示のみの早期帰還＋覚醒上振れの取消。魔力は満額）とし、放置ゲーの文法を守る
   - 魔力素材も毎回獲得し、天井ゲージが目に見えて進む
   - 開封後、**任意でニックネームを付けられる**（§5）

5. **再出発** — また編成して灯す。序盤は「灯す→誰か起きる→また灯す」だけでループが伝わり、チュートリアル説明を要しない

### 初回起動（v2.1）

初回起動時に**モチーフ#1（スライムの精霊）を1体付与**する。★・性格・色は通常ロール。これにより初周から編成が可能で、Widgetが空にならない。特別扱いはこの付与のみで、以降#1は他と同列に排出・重複する。

## 4. 外側のループ（日〜週スケール）

### 収集はハクスラ型

- 図鑑コンプ型ではなく、**同じモチーフでも良ロールが出ると嬉しい**ハクスラ型に軸を置く。図鑑（モチーフ収集）は短期で埋まる前提とし、埋まった後の目標を厳選が引き継ぐ
- 「★4以上・性格一致・レア色」の3軸同時当たりは相当な重複消化を要する＝少ないアセット（初期10体×パレットスワップ）で長期間成立する
- 住人ごとに**感情の方向**（かわいい・かっこいい・ゆるい・不気味・威厳）が割り振られており、「かっこいいのが★5で出た」「かわいいのがレア色で出た」と当たりの嬉しさに種類が生まれる

### 魔力の循環

- **重複・厳選落ち個体は「魔力に還す」**（旧称：変換）。コモンばかりの周も天井進捗として無駄にならない
- 魔力天井の出口は**指名覚醒**（図鑑から選んだモチーフを確定で起こす。★・性格・色は通常ロール）で確定（設計書03）
- 「溢れた重複 → 魔力 → 狙い撃ち」という厳選ループの循環を作る
- 「魔力に還す」は愛着の敵になりうるため、手動操作のみ・保護フラグあり・世界観上の言い換えで守る

### 遺跡の成長

- 住人が増える → 遺跡が賑わう → 背景テーマ解放（収集の成果がWidgetの見た目に還元される）
- 天気・曜日祭壇・月齢（権限不要の疑似イベント）は修正値として毎日差し込まれ、**性格（雨好き・夜行性等）や器の材質と噛み合う編成を見直す動機**になる（対応表は設計書02 §5.3）
- 天気や曜日は現実から来るため、**自分の遊ぶ時間帯・曜日に合う性格が、その人にとっての当たり**になる。厳選の目標が人ごとに変わることを性格軸の売りとする

## 5. 個体差システム（厳選3軸・確定）

住人1体ごとに以下の3軸をロールする。**サイズ振れは採用しない**。**再抽選・性格付け替え手段は実装しない**。厳選の緩和は排出分布の定数調整のみで行う。

| 軸 | 内容 | 備考 |
|---|---|---|
| 個体値 | 単軸の総合値「★1〜5」 | 回収画面の★表示で当たり/外れが一目で伝わる |
| 性格 | 特性1枠、**12種**（v2.2確定） | 既存の攻略軸（天気・時間帯・曜日・月齢・回収量）に1対1でフック。性格テーブル＝攻略の説明を兼ねる（表は設計書02 §5.3） |
| 色 | 通常色→レア色→発光色 | ステータスに影響しない。**レア色＝器の色違い、発光色＝精霊質が全身に満ちた状態** |

### ニックネーム（v2.1・個体差ではない愛着装置）

- 個体に**ユーザーが名前を付けられる**。ロール対象外・ステータス無関係
- 最も安く効く愛着装置として採用。開封直後とコレクション一覧から任意で設定
- 未命名時はモチーフ名を表示

### 排出分布（PoC用・緩め設定、全定数テーブル化）

| 項目 | PoC初期値 |
|---|---|
| 覚醒数/周 | 1体以上確定（戦果で上振れ） |
| ★1〜3／★4／★5 | 85%／12%／3% |
| 性格 | 全12種等確率 |
| レア色／発光色 | 8%／1% |

デモ用定数セット（短縮探索時間・高排出率）を本番値と分離して持つ。

## 6. リザルト：ログ形式（確定）

- ローグライク系の**流れる戦闘ログ**で表現する。戦闘シーンの描画はしない
- 探索終了時に一括生成したログを、帰還後の回収画面で流す。リアルタイム処理不要
- 感情表現は姿勢差分ではなく、**開封カードの演出**（レア色以上の背景・発光）が担う（v2.1：主人公3姿勢の流用を廃止）
- ログの末尾が開封（覚醒個体のロール開示）に接続する

## 7. 攻略要素の軸（既存資産の転用）

| 攻略軸 | 転用元 |
|---|---|
| サイズクラス→ロール | S＝支援・群れ、M＝アタッカー、L＝壁。アート仕様のS/M/L分類がそのまま編成の意味を持つ |
| **器の材質→属性相性**（v2.1／v2.2改訂） | 水・土器・石・骨・金属・火・**植物**の7種（v2.2で#10 供物の果実のために植物を追加）。旧「生き物／無機物」を置換（全住人が精霊質を宿すため、生き物か否かは分類にならない）。**PoCの相性は天気・曜日祭壇との相性のみ**。材質同士の相性は、敵の傾向を事前に見せる仕組みとセットで製品版 |
| 天気・曜日修正値→編成の動機 | 「雨の日は水・土器が有利、火は不利」「木曜は植物の祭壇」等。権限不要の疑似イベントが毎日編成を見直す理由になる。最も安く効く攻略要素。相性が攻略になるのは**点火前に見えるもの**に限るため、天気・曜日・月齢は編成画面に表示する |
| 性格→修正値へのフック | 個体差の性格軸が上記の各修正値系に1対1で接続。厳選の成果がそのまま攻略になる |
| 深度 | ランタン強化＝より深い層＝強い寝ぼけ個体＝良いドロップ |

## 8. 設計判断の根拠

### 8.1 ランタン一本化の理由（不変）

- **ランダム性の置き場所を移動**：「いつ終わるか」は確定、「何を持ち帰るか」は開けるまで不明
- **技術面**：終了時刻が開始時点で確定するため完全ローカル完結
- **審査面**：「明確な終了時刻を持つ進行中イベント」は配達・ナビと同じ構造であり、Live Updatesのpromoted要件の通過性が上がる見込み

### 8.2 住人＝毎周報酬への転換理由（不変）

- コア（住人収集）の快感が毎周発生しないと、序盤に「何をすればいいか」が伝わらない
- 重複を許すからこそ少ないアセットで回る。個体差3軸により重複自体が開封価値を持つ

### 8.3 主人公廃止の理由（v2.1）

主人公概念は3つの機能を束ねていたが、v2で各機能に別の担い手ができた。

| 元の機能 | 担い手 |
|---|---|
| 探索の実行者・案内役 | 隊長（編成[0]） |
| 世界観のシンボル（アイコン・通知） | ランタン（＝コア機構そのもの） |
| 序盤の画の穴埋め | 留守番役の小物＋初回起動時の初期付与1体 |

主人公を残すと「主人公が重複ドロップして魔力に還る」矛盾が生じ、隊長概念の価値も薄まる。解体して分配するのが正しく、発注量も減る（3姿勢×2〜3コマの取り下げ）。

### 8.4 精霊質による統一と、感情の多様性（v2.1）

- 器の名前（「壺」）だけでは絵にすると物体になるため、住人は**器×中身×振る舞い**の3要素で定義する
- 中身を全住人共通の**精霊質**にすることで、世界観の追加なしに「生きている」目印（精霊質が露出する目）を全個体に課せる
- 統一を担うのは精霊質の色・目の描法・出自の3点のみ。頭身・シルエット・感情の方向は住人ごとに自由とし、かわいい／かっこいい／ゆるい／不気味／威厳を割り振る

### 8.5 発掘袋の扱い（不変）

終了条件・ゲージUIとしては削除。表示専用の演出として存続。

### 8.6 バトル導入がコアループに与える影響（不変性の確認）

- ランタン方式の確定性（終了時刻・ローカル完結）は一切変更しない
- ステップ1に編成、ステップ4に戦果（★分布シフト）が加わるのみ
- アート仕様の各原則には抵触しない。個体差はすべて数値・パレットスワップで表現され追加作画ゼロ

## 9. 技術・審査面の確定事項

### 常駐・通知まわり（不変）

- `POST_NOTIFICATIONS` 許諾は「権限不要方針」の唯一の例外。初回探索開始の直前に「精霊の帰りを知らせるため」と文脈付きで要求する
- `POST_PROMOTED_NOTIFICATIONS` はマニフェスト宣言のみの非ランタイム権限
- フォアグラウンドサービスは使わず、常駐通知＋AlarmManager/WorkManagerで検証する
- Live Updatesの制約：チップ内にカスタムRemoteViewsは置けない。世界観表現はWidget側、チップは「気配」に徹する（チップのアイコンは**ランタンのモノクロシルエット**）

### バトル・ロールまわり

- バトルおよび**覚醒個体のロール（★・性格・色）は、探索終了時（または回収時）にシード値から一括計算する決定論的処理**とする。サーバー不要・ローカル完結を維持
- 初期付与1体もシード注入可能な通常ロールで生成し、決定論を保つ
- **住人ロール（毎周確定覚醒＋3軸）はコア体験そのものであり、PoCに含める**
- **PoCのバトルは成否判定のみの最小版**（MinimalBattleResolver、v2.2確定）。性格12種のうち10種が鎮めに効くため、バトルを外すと「性格一致」を狙う厳選が意味を失う（設計書02 §5.1〜5.2）

### 天気・疑似イベント（v2.2）

- 天気は**ユーザーが選んだ固定地域の「今日の天気」（予報）**を使う。地域は編成画面ヘッダから開くダイアログで都道府県を選ぶ。設定画面は作らない。位置情報権限は使わない
- 取得元は気象庁の予報JSON（差し替え可能なインターフェースの裏に置く）。取得は編成画面表示時などに非同期で行い、**点火はネットワークに触れず保存値を読むだけ**（1タップ点火とオフライン点火を守る）
- 地域が未設定、または保存値が6時間より古いときは**中立**（天気に関わる性格・材質の効果がすべて不発）。誰かだけが得をしないようにする
- 曜日祭壇・月齢は日付から機械的に導出する。**六曜はPoCでは使わない**（旧暦変換が必要で誤りやすいため）
